部署条件已明确为长期在线、不经过 OpenClash、共用 AdGuard Home DNS 的 PT 专用 Linux 主机。因目标没有 Node.js/Python，实现已迁移为标准库 Go 程序，以关闭 CGO 的 Linux 二进制部署。现有 JSON 配置继续使用。

PT 主机无法直连 GitHub，现支持 `.env` 配置 OpenClash mixed HTTP 代理，仅用于名单下载；`config.proxy.example.json` 启用远程来源和快照兜底。测速、API 与 DNS 始终直连，不使用全局代理环境变量。默认每 24 小时在运行时刷新，失败保留缓存；离线 config.pt.example.json 仍可使用。`.env` 与配置同目录，权限建议 0600。用户确认使用 systemd，现提供每小时完整优选模板。

已验证目标健康接口可返回有效 OpenBao 响应。家庭扩大候选池后的实测初筛 130 个地址，9 个地址通过全部五次 HTTPS 健康检查，本轮建议 `104.17.128.164`，TTFB 中位数约 522ms。Mac 出口的测试仅验证功能，不能据此选址。当前工具的使用、配置和限制见 README.md。

## 目标与边界

在家中独立 Linux 主机上，通过与客户端相同的网络出口测量候选 Cloudflare IP，选择能够可靠服务目标域名的地址，通过 AdGuard Home API 更新指定域名的 DNS rewrite。

- 首个使用场景是 `openbao.example.com`，域名、端口、测速 URL、AdGuard Home 地址均来自配置。
- 首版支持一个目标域名，仅使用 IPv4；IPv6 不在项目范围，多域名和 HTTP/3 暂不作为实现前提。
- 不修改路由器网络配置，不接管其他 DNS rewrite，不维护 Web 管理界面。
- 目标服务为 OpenBao，没有可供测速的大文件。首版以 API 可用性、响应延迟和历史稳定性为核心，不进行下载带宽排名。
- 衡量的是这个出口访问指定服务的表现，不承诺 IP 永久最快，也不把其他站点的测速成绩等同于目标服务成绩。用户已澄清无需限定 Unicast。

## 候选 IP 来源

Cloudflare 官方公开的常规 CDN 网段属于 Anycast。首版从这些网段构建候选池，不能认为 Cloudflare 的其他产品地址都能服务目标域名。

首阶段验证来源与实际兼容性，以公共列表补充官方 CDN 网段的有限采样：

- 使用可审阅的本地候选文件；每个地址保留来源和获取时间，允许手动补充候选。
- 从官方 CDN 网段分散采样，不枚举整个地址空间；限制每轮数量，跨轮轮换采样，并始终加入当前 rewrite IP 和最近可用的备用 IP。
- 官方网段是可信的候选来源，不代表其中每个地址当前都能服务目标域名；入围必须通过实际 HTTPS 验证。
- 如果后续接入远程列表，明确允许的源，限制下载大小、更新时间及候选数量；更新失败使用最近有效副本。
- 校验 IP/CIDR，去重；拒绝私网、回环、多播等不应作为 CDN 候选的地址。CDN 候选校验与 AdGuard Home 的内网地址配置分开。

不依赖未经验证的社区 Unicast 列表；若官方网段采样效果不佳，再有针对性地研究其他来源。

## 测试方法

所有候选测试固定连接指定 IP，同时保留目标域名的 Host 和 TLS SNI，正常验证目标域名证书；不关闭 TLS 校验。显式控制连接，避免现有 DNS rewrite 让所有测试实际上访问同一 IP。

首版使用 HTTPS/TCP；连接阶段单独采样，避免连接复用掩盖新建连接耗时。跨域重定向不能自动当作原候选的成绩，需明确报错或按配置处理。

| 阶段 | 测量内容 | 用途 |
| --- | --- | --- |
| 连通初筛 | TCP 建连耗时、超时及失败次数 | 快速淘汰不可达候选 |
| 目标兼容性 | TLS 验证、HTTP 状态、预期响应特征 | 排除错误站点、挑战页、无效 CDN 入口 |
| 应用延迟 | TLS 耗时、首字节时间，统计中位数和 P95 | 衡量实际请求等待及长尾 |
| 历史稳定性 | 近期请求成功率、超时率、延迟波动、样本年龄 | 避免单次低延迟掩盖长期不稳定 |

TCP/HTTP 失败率称为请求失败率，不冒充网络层丢包率。OpenBao 的小 JSON 响应无法可靠测量带宽，不把这类响应的字节数除以耗时当作链路带宽。

首选 `GET /v1/sys/health`，预期响应为健康状态 JSON；根据实际版本与部署确认 `initialized`、`sealed`、`standby` 等字段语义。该端点可用于无 OpenBao token 的健康探测，不读取或写入任何业务秘密，也不要求提供 root token。若边缘访问控制限制了该端点，应明确配置访问方式，不能通过关闭保护解决。

把结果分为线路连接、目标响应和服务状态三类。OpenBao 的健康接口可能以 429 表示 standby，503 可能表示 sealed；结合响应 JSON 判断，不能仅把非 200 当作线路失败，也不能把任意 429 当作正常 standby。所有候选都返回 sealed 等状态时，报告服务故障，不靠换 IP 修复。

新建连接延迟与连接复用下的 API 响应延迟分别记录，后者更接近常用 SDK 的访问。小响应限制最大读取字节数、超时、请求速率和每轮总请求数，避免给 OpenBao/WAF 增加无意义负担。首轮建议有限数量的 TCP 初筛，只让少量入围地址进行多轮健康接口采样。

历史统计保留样本数量；P95 只有在窗口内样本足够时才参与排名，少量请求仅展示原始耗时和中位数。各候选交错采样，降低时段差异对比较的影响。

公共下载测速不进入首版；以后确实需要带宽诊断时，作为独立可选功能，不能替代 OpenBao 的目标服务成绩。

保留正常 DNS 访问作为对照。获取对照地址时必须绕过本程序维护的 rewrite，否则会形成反馈循环；对照解析器同样来自配置。

## 选择与切换策略

优先使用清晰的分层选择规则，不在第一版引入难以解释的加权总分：

1. 通过目标域名兼容性与最低成功率要求，样本足够新；不合格候选直接淘汰。
2. 按稳定性门槛筛选，再比较 API 响应的 P95 与中位数；相近时优先保留当前地址，避免为了很小的延迟差改变 DNS。
3. 每轮测当前 IP；候选要超过有意义的改善阈值并连续胜出才切换。
4. 设置最短切换间隔；当前 IP 连续不可用且备用通过即时复验时，可以绕过正常冷却时间。
5. 新候选样本不足时先观察。历史成绩过期后不能直接用于故障切换。

待试测调整的起始参数：完整优选每小时一次，当前地址健康检查每 5 分钟一次；正常切换要求连续两轮胜出、关键指标改善约 15%，切换冷却 30 分钟。所有参数可配置，指标阈值须区分方向和单位。

检测本机网络、DNS 或目标服务整体故障，避免把共同失败误判为所有 IP 都劣化。没有合格候选时默认保留现有 rewrite 并记录失败，不写入未验证地址。自动恢复原始解析属于可选配置策略，需记录被接管前的状态并限定只恢复本程序管理的规则。

## AdGuard Home 更新事务

依据用户已验证的 Basic Auth API：

1. `GET /control/rewrite/list`，精确定位配置域名的现有规则。
2. 无规则时使用 `POST /control/rewrite/add`；存在一条明确受管理的 IPv4 规则时，用原始 domain/answer 作为 target 调用 `PUT /control/rewrite/update`。
3. 新旧地址相同时跳过写入。遇到多条冲突记录、CNAME、禁用规则或无法明确归属的记录时停止更新，给出可操作的错误；不自行删除或启用用户规则。
4. 写前再次读取，发现人工修改则放弃本轮写入。API 不提供原子 compare-and-swap，重读只能缩小竞争窗口，仍需在写后核对。
5. API 成功后回读规则，再直接查询配置的 AdGuard Home DNS 服务，验证实际 A 响应；同时检查 AAAA 和 HTTPS/SVCB 的实际行为。
6. 使用正常 DNS 解析重新访问目标服务，验证实际连接 IP 和业务响应。HTTP 200 的 API 响应不等于客户端访问已经生效。
7. 写后确认新地址无法服务而旧地址仍健康时，回滚；回滚前确认规则仍是本次写入结果，避免覆盖人工修改。

网络超时后不盲目重复变更请求，先读取确认实际状态。401/403 是认证或权限故障，直接报告；临时网络故障有限重试。通过运行锁避免同一主机的定时任务与手动执行互相覆盖。

DNS API 地址与 DNS 查询地址分别配置，例如管理端口和 DNS 端口不要求相同。DNS 缓存和已有 TCP/QUIC 会话可能继续使用旧地址；实际客户端验证是验收的一部分。首版不会自动修改全网 IPv6、DoH 或缓存设置。

## 技术与配置

采用 Go 命令行程序，使用标准库网络、TLS、JSON 和测试设施，无第三方依赖。开发电脑进行交叉编译，目标 Linux 只需二进制、配置、候选列表和系统 CA 根证书，不要求安装编程语言运行时。

通过 `CGO_ENABLED=0` 构建 amd64 与 arm64 版本；目标架构以 `uname -m` 确认。首版不依赖外部测速程序，不引入数据库、任务队列或 Web 服务。PT 上传/下载可能影响网络延迟，需对比低负载和实际负载下的多个时间窗口，不能把主机忙时的单轮失败视为 IP 长期不稳定。

非敏感配置使用 JSON，候选列表使用独立文件。配置包含：

- 目标域名、HTTPS 端口、健康检查 URL、预期响应条件。
- AdGuard Home API base URL、用户名、DNS 查询地址。
- 候选文件、可选源更新参数、对照解析器。
- 超时、并发、采样次数、请求速率与总量预算、最大响应大小、选择阈值和冷却时间。
- 状态文件路径、历史保留期。

域名与 API 地址没有代码默认值；启动时缺少必填项立即报错。健康检查 URL 与目标域名的关系需要校验。

密码方案：

- 开发阶段 `.env` 足够：纳入 `.gitignore`，权限 `0600`，仅提供占位符 `.env.example`，不写进示例命令、日志或状态文件。
- Linux 部署优先支持 `ADGH_PASSWORD_FILE`，通过 systemd `LoadCredential=` 提供密码文件；兼容 `ADGH_PASSWORD` 以便简单部署。二者同时配置时直接报错，避免来源混淆。
- `.env` 与普通密码文件都没有提供静态加密；重点是限制读取权限及避免泄漏。是否采用 systemd credentials 取决于部署版本，不强制增加密钥管理服务。
- Basic Auth 经 HTTP 传输不会加密凭据；只在明确受信任的家庭管理网络使用现有 HTTP API，若已有 HTTPS 则优先使用并正常验证证书。

状态保存为有版本号的 JSON：近期样本、当前选择、切换时间、必要的变更记录和恢复状态。原子写入、限制历史长度；损坏时报告错误，不依赖损坏状态做自动回滚。

## 命令和 Linux 运行

拟提供以下命令，名称在实现时最终确定：

- `probe`：只测速并输出每个 IP 的成绩与淘汰原因。
- `run --dry-run`：完成选择及只读 API 检查，输出拟变更。
- `run`：执行完整优选、条件写入及验证。
- `health`：检查当前地址，必要时复验近期备用后切换。
- `status`：查看最近一次结果、样本年龄及当前受管理规则。

systemd oneshot service + timer 负责周期运行，使用专用低权限账户。程序负责超时、运行锁和可区分的退出状态；日志写入 journald，包含阶段、IP、指标、切换原因和脱敏错误。首版无需额外通知渠道。

## 实施顺序及验收

### 1. 验证方案成立

从官方网段取得有限候选；从家中出口测试少量候选、当前解析地址及正常访问基线。确认候选可以服务目标域名，证书与 OpenBao 健康 JSON 正确，测量具备可重复性。没有可用候选时先解决来源或边缘访问问题，不进入自动改写部署。

### 2. 实现只读测速与选择

建立最小项目结构、配置校验、固定 IP HTTPS 测试、OpenBao 健康响应分类、分层选择、历史状态及 dry-run。通过多个时段的真实试测调整阈值、并发、请求预算与周期。

### 3. 实现安全写入

增加精确匹配的 API 更新、回读、DNS 验证、失败复核和条件回滚；使用模拟服务测试超时、认证失败、重复规则、并发变更及不确定提交结果。先 dry-run，再手动执行一轮实际更新验证。

### 4. Linux 部署与观察

提供 systemd unit/timer、配置示例、凭据与排障文档。在目标 Linux 上验证重启恢复、重复运行、运行锁及计划触发；观察至少一天的实际成绩和切换记录，再调整频率。

验收必须覆盖：

- 目标客户端正常解析到选定 IP，实际 OpenBao 访问正常，并与基线比较 API 响应延迟、长尾和成功率改善。
- 没有更好候选时不写 API，短时波动不会频繁切换。
- 坏候选、TLS 错误、挑战页、整体断网、API 故障不会造成未验证地址写入；standby、sealed、边缘限流等响应能正确分类。
- 写后失败能在满足条件时恢复旧规则，人工修改不会被自动回滚覆盖。
- 无关 rewrite 不变，凭据不进入 Git、日志或报告。
- 请求数量、响应大小、超时、并发和历史容量符合配置限制。
