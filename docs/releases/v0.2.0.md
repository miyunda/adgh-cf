# v0.2.0（待发布）

新增多域名支持：主域名进行性能排名，全部组员通过同一候选 IP 的复验后，才允许更新各自现有的 AdGuard Home rewrite。继承 0.1.1 的日志精简行为。配置格式的 1/2 与软件发布版本 0.2.0 分开管理。

## 更新

- 显式 `schemaVersion: 2` 配置默认检查基本 HTTPS 响应，支持严格 HTTP 条件和 OpenBao 专用健康判断；兼容旧配置默认 OpenBao 语义。
- 最多 4 组、16 个域名、每组 8 个成员；主域名排名、最多前三候选全组复验，以及确认/冷却后的组内对齐。
- HTTPS/HTTP 有限前缀读取、最多 3 次同源 HTTPS 跳转、逐请求预算与总运行时间限制。
- 新增 `--group`、分组报告和独立的格式版本 2 状态文件。多条 rewrite 更新使用持久 pending 日志与逆序条件补偿，无法安全恢复时保留 pending 并阻止后续更新。
- 提供普通网站最小模板 `config.https.example.json`、多域名模板 `config.groups.example.json`、固定目录部署模板 `config.groups.run.example.json` 与 [多域名迁移指南](../DOMAIN-GROUPS.md)。

## 升级

- 旧单域名 JSON 配置、凭据和状态继续可用；仅替换二进制不会自动改写用户配置或启用多域名模式。
- 启用多域名模式时先用旧配置处理 pending，另建 `schemaVersion: 2` 配置和独立 `stateFile`；原 OpenBao 服务显式保留 `mode: "openbao"`，原 HTTP 服务保留预期状态码和内容标记。
- 新 systemd 模板为 `TimeoutStartSec=125min`、`TimeoutStopSec=130s`，覆盖允许的最长正常运行及最多 120 秒恢复。启用多域名模式时更新已安装 unit、校验并 daemon-reload；也可按实际 maxRunSeconds 加至少 120 秒设置启动超时。
- 停 timer、等待本次 service 完成、备份现有二进制和状态，校验包后升级；先 probe/dry-run，再恢复定时运行。禁止新旧任务同时接管同一域名。
- 多域名 JSON 报告结构不同；解析脚本应检查 schemaVersion，并读取 groups。refresh/export 仍是全局候选操作，不接受 --group。
