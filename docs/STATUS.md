## 项目要解决的问题

家中直连 Cloudflare CDN 慢且不稳定，希望定时从候选 IPv4 中选出适合本地出口、能正确服务 OpenBao 的地址，最终通过 AdGuard Home API 自动更新指定域名的 DNS rewrite。

- 当前目标域名为 `openbao.example.com`，健康接口 `/v1/sys/health`；域名、路径和候选源都由 JSON 配置指定，不在代码中硬编码。
- 只使用 IPv4，不要求候选为 Unicast；常规 Cloudflare CDN 地址属于 Anycast。
- 服务没有大文件，优选依据为连接速度、健康接口延迟和成功率；不进行带宽排名。
- 成品运行在家中长期在线的 PT Linux 主机，和客户端共用家庭出口及 AdGuard Home DNS。该主机不经过 OpenClash，且没有 Node.js/Python，因此采用无第三方依赖的 Go 静态二进制。
- 开发 Mac 与家庭出口不同，其测速仅用于功能验证，不能用于家庭选址。

## 已完成

- `probe`：有限并发 TCP 初筛，入围地址交错进行 HTTPS 健康检查；保留域名 Host/SNI、正常校验证书、IPv4 直连。输出原始样本、成功率、中位数和建议 IP；至少 20 个成功样本才给出 P95。
- `refresh` / `export`：刷新公共来源或导出纯 IPv4 快照。两份公共名单按 Cloudflare 官方 IPv4 网段过滤，独立缓存、默认每 24 小时在运行时按需刷新，失败保留旧缓存；离线快照作为备用。
- `.env`：只配置名单下载专用 OpenClash mixed HTTP 代理，地址格式 `IPv4:端口`，支持用户名和密码。与 JSON 配置放在同一目录，建议权限 0600；不写入日志和报告。TCP、TLS、健康检查及 DNS 对照不走代理，不使用全局代理环境变量。
- Linux amd64、arm64 静态二进制及部署包已生成；目标机器只需系统 CA 根证书和配置文件。
- `go test -race ./...`、`go vet ./...`、gofmt 检查通过。测试覆盖代理 CONNECT 认证与 TLS 隧道、代理失败缓存回退、测速直连隔离，以及配置、候选过滤、健康分类和失败边界。
- 用户已在家庭 PT 主机运行新版 `refresh` 和 `probe`，两份名单实际下载成功，候选测速成功，报告写入 `reports/home.json`。

## 2026-10-07 家庭实测

本轮执行 `refresh --config config.proxy.json`，再执行 `probe --config config.proxy.json --output reports/home.json`。报告起止为北京时间 22:54:55–22:56:50，约 115 秒。

- 两个来源分别接受 97 个 IPv4，拒绝 3 / 2 条；随包快照接受 194 个地址。不同池合并时会去重，不能将这些数量相加当作最终候选数。
- TCP 初筛 130 个地址，119 个连接成功，10 个建连耗时低于 200ms。
- HTTPS 测试 11 个地址，每个 5 次；9 个满足全部成功的门槛，均返回 active 健康响应。

| 地址 | 成功次数 | TCP 中位数 | 完整 TTFB 中位数 | 本轮定位 |
| --- | --- | --- | --- | --- |
| 104.17.128.164 | 5/5 | 162ms | 522ms | 本轮建议，TTFB 范围 493–561ms |
| 104.17.142.212 | 5/5 | 159ms | 522ms | 第二名，与第一名中位数仅差约 0.08ms |
| 104.17.139.37 | 5/5 | 185ms | 576ms | 第三名 |

| 104.21.23.90 | 0/5 | 320ms | 全部超时 | 本轮系统 DNS 对照 |
| 172.67.210.35 | 2/5 | 324ms | 2849ms | 本轮系统 DNS 对照，中位数仅计算成功样本 |

`104.17.128.164` 的完整 TTFB 相比 `103.31.4.18` 降低约 28%。完整 TTFB 包含 TCP 建连、TLS 和首字节等待，不能与单独 TCP 延迟混为一谈。五次成功只能证明这一轮表现，尚不能证明长期稳定；前两名的微小差距不应触发自动切换。

数据依据为用户提供的家庭运行报告；这里只保留脱敏统计。完整原始报告不上传仓库。家庭 `reports/home.json` 下次使用同一输出路径会被替换，复测应采用不同文件名保留历史。
